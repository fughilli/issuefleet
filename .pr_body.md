## What & why

Agent containers hold no operator credentials — but nothing stops an agent from
*committing* a secret it generated, pasted, or scraped from its own environment
into its branch. The one outbox action that carries such content **into the
repository** is `ready` (it force-pushes the branch and opens the PR). This adds
a **security gate** that scans the diff a `ready` would push, host-side in the
orchestrator, **before** the push — and rejects a leak with a rationale routed
back into the worker's mailbox so the agent fixes its branch and resubmits.

The rejection uses the same recovery channel as the existing no-commits-ahead
gate: a `reply` into the inbox wakes the worker on its next turn.

## Design

Mirrors the `advisor.py` seam — a `SecurityGate` Protocol with a deterministic
default and an optional LLM backend, behind a `build_gate` factory:

- **`RegexSecretScanner`** (default, `mode="block"`): deterministic, stdlib-only.
  Scans only the *added* lines of `base...HEAD` (so an unchanged secret already
  on the base isn't blamed on this PR) for narrow, high-confidence credential
  shapes — private-key blocks; AWS / GitHub / Anthropic / OpenAI / Linear /
  Slack / Google / Stripe / Tailscale tokens; JWTs; secret-shaped assignments —
  plus newly-added sensitive files (`.env`, `id_rsa`/`id_ed25519`, `*.pem`,
  `credentials.json`, …, with `*.pub`/`known_hosts` exempt).
- **`ClaudeSecurityGate`** (`deep_scan="claude"`): an *additive* LLM pass over
  the added lines that can catch secrets the regexes miss. Every deterministic
  finding stands regardless, and an API failure degrades to the deterministic
  verdict rather than clearing a hit or wedging a submission. Reuses the fleet
  manager's Anthropic key.
- **`NullGate`** (`mode="off"`): scanning disabled.

Two invariants for a security seam:

- **Redaction.** A finding never carries the matched secret verbatim — the
  rejection note, the logs, and the archived outbox receipt are durable
  artifacts, so echoing the key would relocate the leak rather than stop it.
- **Fail closed.** If the diff can't be produced/scanned, `block`/`warn` behave
  conservatively: `block` asks the agent to retry rather than pushing an
  un-inspected diff (`warn` still pushes, by definition).

## Modes

| `mode`  | on a hit                                                        |
|---------|-----------------------------------------------------------------|
| `block` | (default) nothing pushed; agent woken with a redacted rationale |
| `warn`  | logged + note delivered, but the PR still goes out              |
| `off`   | no scanning (`NullGate`)                                        |

## Changes

- `src/issuefleet/security.py` — the gate (scanner, LLM backend, `build_gate`).
- `gitops.diff()` + `Git` port + `FakeGit` — the `base...HEAD` diff to scan.
- `reconcile._security_ok()` wired into `_handle_ready()` after the
  commits-ahead gate, before the push.
- `config` — new `[security]` section (`mode`, `deep_scan`) + validation.
- `cli.build_stack` — resolves and injects the configured gate.
- `doctor` — reports the gate's mode and deep-scan key resolution.
- README + `examples/fleet.toml` — document the block.
- Tests — `tests/test_security.py` (every detector family, redaction, diff
  parsing, line/size handling, the LLM merge/degrade, `build_gate`) and
  reconcile cases (block rejects & wakes the agent without pushing; warn pushes
  but notifies; off passes; scan-error fails closed).

## Known edge

The scan inspects the **net** `base...HEAD` diff, so a secret that was added and
then removed **within** the branch isn't flagged even though it remains in the
branch's commit history (and would still be pushed). This catches the
overwhelmingly common case (a secret committed and still present at HEAD); the
rejection message already instructs the agent to scrub the secret from the
branch *history*, not just the working tree. Scanning every commit's patch
(`git log -p base..HEAD`) would close the gap at the cost of flagging
already-removed secrets — a deliberate v1 tradeoff, easy to revisit.
